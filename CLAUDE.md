# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Deterministic, data-driven Pokémon hero shooter: TypeScript, esbuild, `node:test` via tsx. One Pokémon per player; the shipped modes are the training range and Hold (`src/mods/index.ts`), with co-op waves (T1) and 3v3 hero bots (T2) next. The build is a single static `dist/index.html` deployed to GitHub Pages (`.github/workflows/deploy.yml`). The README has the full picture. This file lists only what a session needs up front. The pivot from the survivor game is recorded in `docs/hero-shooter-pivot.md` (decisions §10, progress and open items §11); the survivor game is on the `survivor-final` tag.

## Commands (repo root)
- One suite: `npx tsx --test tests/<name>.test.ts` (add `--test-name-pattern "<regex>"` to pick a single test)
- All tests: `npm test` (headless, no browser)
- Types: `npm run typecheck` (CI runs it too)
- Before calling work done: `npm run check` (typecheck, tests, production build; writes `dist/`). Four `tests/pointerlock.test.ts` cases are known reds and stop `check` before its build step: run `npm run build` (or a private build, below) by hand, and report any other red.
- Replay baseline: `npx tsx scripts/checksum.ts [scenario|all] [--update]`. It runs the ten scenarios of `tests/fixtures/scenarios.ts` (scripted input tracks on the range, Mt. Moon, Shoal Grotto, Cinder Crater, a Shrine Gorge Hold, the swap range) and compares their 10 s checkpoints and end hash with `tests/fixtures/replays.json` (`tests/replays.test.ts` asserts the same in `npm test`, plus each scenario's coverage counters). A sim change that is not meant to change behaviour must print every scenario "as recorded"; a hash that moves is a stop, not something to re-record. `--update` rewrites only the scenarios it ran, and the commit that changes the fixture says why. A new feature may land flagged off with a scenario that must print the baseline; retire the flag and its off path once it defaults on and is accepted (docs/hero-shooter-pivot.md §7).
- Performance-sensitive sim changes: `npx tsx scripts/perf-sim.ts 500 --repeat 3 --gate` (the crowd of `scripts/lib/crowd.ts`; baseline p95 0.689 ms, p99 0.936 ms; `--aim` adds the crosshair ray).
- Movement, collision or navigation changes: `npx tsx scripts/navwalk.ts all 5` (real walkers of every size class reach every mandatory space, 0 failures; docs/SIZING.md) and `npx tsx scripts/stuckwatch.ts all 3` (live deadlock watch; current output: 14 player episodes, 3 TRAPPED at River Gorge seed 3, 31 enemy episodes, all logged in pivot §11; compare before and after, a new TRAPPED is a failure).
- Dev server: `npm run dev` (http://localhost:5173)

## Architecture rules (details in README §Architecture)
- `src/sim/` and `src/world/` never import `render/`, `ui/`, `audio/`, `input/` or `assets/`. They must run in Node.
- Fixed 1/60 s ticks, one RNG stream per system (spawn, combat, world, ai). No `Math.random`, and no clock in sim or worldgen output (`performance.now()` is used for timing metrics only).
- Tunable numbers live in `src/rules/` (`defaults.ts` and friends). Systems read `ctx.rules`, never literals. Kept switches are real tunables (`hazards.enabled`, `aim.foliageCover`, `aim.deviceAssist`, the `caps` sub-flags); do not add an off path for an accepted feature.
- The sim emits events. Render, audio and UI only react to them.
- Modes and mods (`src/mods/`): a `Mode` is rule overrides plus `Mod`s; a mod adds, removes or replaces systems. `MODES` (reachable by `?go=1&mode=`) is `[RANGE, HOLD]`; the title offers `TITLE_MODES`, `[RANGE]` (Hold is URL-only until T2: `?go=1&mode=hold&map=<habitat>`); `RANGE_SWAP` is the opt-in swap system's own mode. `RANGE` (with `noSurvivorLoop` and `solo`) is also the plain foundation tests and gates run on.
- Heroes: stats on the level-50 canon curve (`src/rules/stats.ts`), kits from `openingMove` / `heroKit` with authored `HERO_KITS`, the hero pick from `PROTOTYPE` / `FEATURED` (`src/rules/heroes.ts`, docs/HEROES.md). A `KIT_TUNING` test refuses a new unlogged power-0 damaging move in a kit.
- Each subsystem has a doc in `docs/` (HEROES, RANGE, SQUAD, SYSTEMIC, SPAWNING, SIZING, LOCOMOTION, CONTROLS, HAZARDS, HABITATS, LOCATIONS, WORLDGEN, THIRD_PERSON, CAMERA, AUDIO, …). Read the matching doc before changing a subsystem, and update it when its rules or numbers change. `docs/CUSTOMISING.md` is the how-to for roster, size, map and target changes.
- Enemies come from target sets (`src/rules/targets.ts`, `src/sim/targets.ts`), the Hold's `RAID_PARTY` (`src/sim/modes/hold.ts`) and, in tests and gates only, `scripts/lib/crowd.ts` (not a game system; no replay scenario uses it). There are no spawn pools, no director and no elite, alpha or boss roles. The role bits are `raider` and `target` (set by the spawner) and `ranged`, `healer`, `swarm`, `flying` (set by `spawnEnemy` from the species). Per-species facts (preferences, restrictions, size pins) live in `src/rules/profiles.ts`, placement in `src/sim/placement.ts`. Sizes come from `rules.size` through `bodyOf` / `enemyRadius` / `partnerRadius` / `footprintOf` / `partnerFootprint` (`src/rules/sizing.ts`); never derive a body radius in the sim. Walls stop footprints through `World.moveBody` only, and wide footprints route on `src/world/navblocks.ts`, which the location `wide` gate also reads.

## Habitat maps (`src/world/habitat/`, `docs/HABITATS.md`)
- A layout is fully determined by recipe + variant + seed + `HAB_VERSION` (`src/world/habitat/index.ts`). A generator change that alters any accepted layout needs a `HAB_VERSION` bump. Compare timing and retry behaviour against `docs/habaudit/baseline.json`. The navigation profiles (`profilesFor`, `src/world/habitat/mode.ts`) are frozen constants; making a hero of one of the 54 ready species that exceed them is a planned `HAB_VERSION` bump with a regenerated baseline (pivot §11).
- Gates to run after touching habitat, hazard or objective code: `npx tsx scripts/habstate.ts`, `scripts/habplay.ts all 6 1 --raid` (the shorter `all --raid` runs 0 cases and exits 0), `scripts/hazplay.ts`, `scripts/habaudit.ts` (slow; it rewrites `docs/habaudit/baseline.json`, so diff it and restore it unless the change is meant to move it). `tests/habitat*.test.ts`, `habstate`, `habaudit`, `habtac` and `hazards` assert the same checks.
- Hold Raid party: it spawns at team B's staging, 33–47 m from the point. `rules.enemy.despawnDistance` (46) relocates any enemy that is not pinned farther than that from the player to a ring ahead of them, which would skip the approaches. `src/sim/enemies.ts` pins the Raiders of an active habitat Hold and every training target. Check the same relocation before adding any other far-spawned actor on these maps.
- Tactical playtest evidence (survivor build, with a hero-core status note), seeds worth replaying and the human checklist: `docs/HABITAT_PLAYTEST.md`. The current Hold read is the fighting probe in pivot §11.

## Generated and oversized files
- Generated by `scripts/build-content.mjs`; do not hand-edit: `src/content/pokedex.ts`, `src/content/art.json`, `src/content/icons.json`, `src/content/catalogue.ts`, `content/report.json`.
- `src/content/catalogue.ts` (130 KB) is the reference catalogue, not game species: regenerate it alone with `node scripts/build-content.mjs --catalogue-only` (add `--catalogue-out <dir>` for an isolated copy). Authored input is `content/catalogue.json`; read it through `src/rules/catalogue.ts`. Nothing in `src/sim/`, `src/world/`, `src/render/`, `src/ui/` or `src/rules/species.ts` may import it — a catalogue record inside `SPECIES` takes a registry index and moves every replay hash. `tests/catalogue.test.ts` is the gate.
- Never read these whole. Use grep or targeted ranges: `src/content/art.json` (3 MB), `src/content/icons.json` (470 KB), `content/report.json` (290 KB), `docs/Pokemon_*_Specification.md` (90–230 KB). The `docs/*.xlsx` and `content/preview/*.png` files are binary.

## Browser checks
- `tools/*.mjs` and `tests/browser/*.py` drive headless Chromium. Playwright is not a dependency: run `npm i --no-save playwright` first. Usage is in `tools/README.md`. `tests/browser/range.py` is the merge check (title, hero pick, fire at a dummy, a Breakthrough), run by hand, not in `npm run check`.
- Capture mode (`?capture=1`): the sim only steps through `pokewatch.advance(seconds, {frames})`, which runs `round(seconds/frames/dt)` steps per frame. Pass `frames = seconds × 60` (one step per frame). Anything else silently under-steps (`advance(1.4, {frames: 70})` runs 1.17 s) and particles never appear.

## Parallel sessions
- Several Claude sessions often work in this checkout at once. Check `git status` before editing, and leave alone uncommitted changes you didn't make.
- `npm run build`, `npm run dev` and `npm run check` all write `dist/`. For screenshot captures, build into a private directory instead: copy `scripts/build.mjs` to your scratchpad with the output path changed, then pass that HTML to `tools/cap.mjs`. This keeps you from overwriting another session's build.

## Agent skills
- `/grilling` before committing to a change with undecided design questions whose wrong answer is expensive to undo — e.g. a `HAB_VERSION` bump, a regenerated baseline, moved replay hashes, or a contract other systems read (hazards × objectives × enemies). Not for mechanical work — the decisions are already made and only transcription is left.
- `diagnosing-bugs` for a bug or regression with no deterministic repro yet (wrong sim behaviour at a known seed, a hash that moved unexpectedly, a layout failing a gate, a `perf-sim --gate` regression). Not for a failing test that already names its cause.
- Both are vendored in `.claude/skills/`; see `.claude/skills/README.md` for provenance and local edits. Review stays the built-in `/code-review`.
